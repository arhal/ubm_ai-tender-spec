# ERPNext Module Documentation: AI Tender Management

**Version:** 1.0
**Date:** 2025-05-02

## 1. Introduction

This document outlines the specifications for a new module in ERPNext, tentatively named **"AI Tender Management"**. The primary goal of this module is to streamline the process of managing sales tenders by integrating Artificial Intelligence (AI) capabilities.

The module will allow sales personnel to:
*   Create and track tender opportunities.
*   Upload relevant tender documents (RFPs, technical specs, etc.).
*   Leverage AI to automatically analyze documents, extract key information, assess feasibility, and suggest risks/evaluation criteria.
*   Receive AI-powered strategic recommendations for winning the tender.
*   Build quotations directly within the tender record.
*   Generate draft proposals with AI assistance.
*   Finalize and export proposals.

This module aims to significantly reduce manual effort, improve the quality of tender analysis and proposals, and increase the sales team's efficiency and win rate.

## 2. Core Concepts & Terminology

*   **Tender:** Represents a single tender opportunity being pursued. This will be the central Doctype of the module.
*   **AI Analysis:** The process where uploaded tender documents are sent to an external AI service (e.g., via webhook or direct API call) for processing. The AI extracts structured data and provides insights.
*   **AI Strategy Suggestions:** Recommendations generated by the AI based on the tender analysis, aimed at improving the chances of winning.
*   **AI Proposal Generation:** AI assistance in drafting the initial proposal content based on tender details and company information.
*   **Tender Status:** Tracks the current stage of the tender within the workflow (e.g., New, Analyzing, Analysis Complete, Strategy, Proposal, Finalized, No-Go).

## 4. Workflow & UI Description

The module follows a sequential workflow, visually represented by the status indicators at the top of the page (Upload -> Analysis -> Strategy -> Proposal -> Finalize).

**Step 1: Create New Tender**

1.  **Access:** User navigates to the `Tender` List and clicks "New".
2.  **UI:** Display the form shown in `Figure: tender2.jpg`.
3.  **Fields:** User fills in `Tender Name`, `Client Name`, `Description` (Optional), `Due Date` (Optional).
4.  **Action:** User clicks "Create Tender" (or ERPNext's standard "Save").
5.  **System Action:**
    *   A new `Tender` record is created.
    *   `created_by_user` is set automatically.
    *   `status` is set to `New`.
    *   The user is redirected to the main Tender page (`Figure: tender3.jpg` view, initially without analysis results).

**Step 2: Upload Documents**

1.  **Access:** User opens an existing `Tender` record (Status: `New`).
2.  **UI:** The page displays sections similar to `Figure: tender3.jpg`. The "Upload Documents" section is prominent.
3.  **Action:** User drags & drops or browses to upload relevant tender files (PDF, DOCX, XLSX, images, etc.). These files become standard attachments to the `Tender` doctype.
4.  **UI:** Uploaded documents are listed below the upload area (`Figure: tender3.jpg` - "Uploaded Documents").
5.  **Action:** Once documents are uploaded, the user clicks the "Start AI Analysis" button.
6.  **System Action:**
    *   Change `status` to `Analyzing`.
    *   Display a loading indicator to the user.
    *   **Trigger AI Analysis:** Initiate the AI analysis process (See Section 5: AI Integration). This should be a background job.

**Step 3: AI Analysis & Review**

1.  **System Action (Background):** The AI process fetches the attached documents, performs analysis, and sends back the results.
2.  **System Action (On Completion):**
    *   Update the `Tender` record fields with the extracted data received from the AI (Project Scope, Key Dates, Evaluation Criteria, Risk Factors, AI Recommendation, etc.).
    *   Change `status` to `Analysis Complete`.
    *   Notify the user (optional).
3.  **UI:** The `Tender` page now displays the populated "Analysis Results" section (`Figure: tender3.jpg`). The "AI Recommendation" section shows the Go/No-Go verdict, confidence, and key factors.
4.  **Decision Point:** Two buttons are presented:
    *   `Proceed (Go)`
    *   `Do Not Proceed (No-Go)`
5.  **Action (No-Go):** User clicks `Do Not Proceed (No-Go)`.
    *   **System Action:** Change `status` to `No-Go`. Add a visual indicator (e.g., red badge) to the record/list view. The workflow ends here for this tender.
6.  **Action (Go):** User clicks `Proceed (Go)`.
    *   **System Action:** Change `status` to `Strategy`. Navigate the user to the Strategy & Quotation view.

**Step 4: Strategy & Quotation**

1.  **Access:** User proceeds from Step 3 (Go) or opens a `Tender` with `status` = `Strategy`.
2.  **UI:** Display the view shown in `Figure: tender4.jpg` and `Figure: tender5.jpg`.
3.  **Content:**
    *   **AI-Suggested Winning Strategies:** Display the `ai_suggested_strategies` field content (read-only).
    *   **Quote Builder:** Display the `quote_items` child table.
4.  **Actions (Quote Builder):**
    *   User clicks "+ Add First Item" / "+ Add Item".
    *   A dialog appears (`Figure: tender6.jpg`) to enter `Description`, `Quantity`, `Unit Price`.
    *   Clicking "Add Item" in the dialog adds a row to the `quote_items` table and updates the `total_quote_value`.
    *   Users can edit/delete quote items.
5.  **Action:** User clicks "Continue to Proposal".
6.  **System Action:** Change `status` to `Proposal`. Navigate the user to the Proposal view.

**Step 5: Proposal Generation & Editing**

1.  **Access:** User proceeds from Step 4 or opens a `Tender` with `status` = `Proposal`.
2.  **UI:** Display the view shown in `Figure: tender7.jpg`.
3.  **Content:**
    *   **Proposal Editor:** A rich text editor displaying the content of the `proposal_draft` field.
    *   **Boilerplate Text:** A section listing available boilerplate text snippets (from `Tender Boilerplate` child table or a separate linked Doctype). Each snippet has an "Insert" button.
4.  **Actions:**
    *   **Generate with AI:** User clicks "Generate with AI".
        *   **System Action:** Trigger AI Proposal Generation (See Section 5). The AI should receive context (tender analysis, quote details) and generate a draft. The response populates the `proposal_draft` editor. This should ideally run as a background job with a loading indicator.
    *   **Insert Boilerplate:** User clicks "Insert" next to a boilerplate item.
        *   **System Action:** Insert the boilerplate content into the editor at the current cursor position.
    *   **Manual Editing:** User directly edits the content in the `proposal_draft` editor.
    *   **Save Draft:** User clicks "Save Draft" (or standard ERPNext Save).
        *   **System Action:** Save the current content of the editor to the `proposal_draft` field.
5.  **Action:** User clicks "Continue to Finalize".
6.  **System Action:** Ensure the proposal is saved. Change `status` to `Finalized`. Navigate the user to the Finalize view.

**Step 6: Finalize Proposal**

1.  **Access:** User proceeds from Step 5 or opens a `Tender` with `status` = `Finalized`.
2.  **UI:** Display the view shown in `Figure: tender8.jpg`.
3.  **Content:**
    *   **Proposal Preview:** A read-only preview of the final `proposal_draft`.
    *   **Export Options:** Buttons/Cards for:
        *   `Export as PDF`: Generate a professional PDF document (requires a print format). Include company logo/styling.
        *   `Export as DOCX`: Generate an editable Word document.
        *   `Finalize Tender`: Mark the tender process as complete in the system.
4.  **Actions:**
    *   User clicks `Export as PDF` or `Export as DOCX`.
        *   **System Action:** Generate and download the respective file format based on the `proposal_draft` content and potentially a standard template/print format.
    *   User clicks `Finalize Tender`.
        *   **System Action:** Mark the tender as completed (perhaps lock the record from major edits, confirm status remains `Finalized` or move to a new `Completed` status if needed). This signifies the end of the *preparation* workflow within this module.

## 5. AI Integration

This is a critical component. Choose one of the following integration strategies:

**Option A: Webhook Integration (using n8n or similar)**

1.  **Trigger:** ERPNext button clicks ("Start AI Analysis", "Generate with AI") trigger a client-side script or server-side script that calls a specific ERPNext webhook endpoint.
2.  **Webhook:** The webhook call passes necessary data (e.g., `Tender` document ID, list of attached file IDs, current tender data for proposal context) to an external workflow tool like n8n.
3.  **n8n Workflow:**
    *   Receives the webhook trigger.
    *   Retrieves files from ERPNext (if needed, using ERPNext API).
    *   Calls the relevant AI API (e.g., Google Gemini API) with the documents/data and appropriate prompts (prompts need careful design).
        *   *For Analysis:* Prompt to extract specific fields, identify risks, evaluate criteria, recommend Go/No-Go.
        *   *For Proposal:* Prompt to draft a proposal based on tender info, company profile, quote items.
    *   Parses the AI response.
    *   Updates the corresponding `Tender` record in ERPNext using the ERPNext REST API.
    *   Handles potential errors during the process.
4.  **Pros:** Decouples AI logic from ERPNext core, potentially easier to manage complex AI interactions and API changes, leverages existing n8n expertise.
5.  **Cons:** Introduces an external dependency (n8n), potential latency, requires managing the n8n instance and workflows.

**Option B: Direct API Integration (Frappe/Python)**

1.  **Trigger:** ERPNext button clicks trigger a server-side Python function within the `Tender` Doctype's controller (`.py` file).
2.  **Server-Side Script:**
    *   The Python function gathers necessary data (attached file paths, tender data).
    *   Reads file content directly from storage.
    *   Uses Python libraries (`requests`, or specific AI SDKs like `google-generativeai`) to call the AI API directly.
    *   Sends data/files and appropriate prompts.
    *   Receives and parses the AI response.
    *   Updates the `Tender` document fields (`doc.save()`).
    *   **Crucially:** Long-running AI calls MUST be enqueued as background jobs (`frappe.enqueue`) to avoid timing out the user request and blocking the UI. The UI should show a loading state until the background job completes (potentially via polling or WebSockets).
3.  **Pros:** Tighter integration within ERPNext, potentially lower latency, fewer external systems to manage.
4.  **Cons:** Can make ERPNext code more complex, requires careful handling of background jobs and error states, API keys need secure management within ERPNext.

**Recommendation:**

*   If your team is comfortable with n8n and prefers decoupling, **Option A** is viable.
*   For a more integrated feel and potentially better performance (if background jobs are implemented correctly), **Option B** is often preferred for ERPNext development. Ensure robust background job implementation.

**Regardless of the method:**
*   **API Keys:** Securely store AI API keys (e.g., in a custom Settings Doctype, environment variables).
*   **Prompts:** Design effective prompts to guide the AI for each task (analysis, strategy, proposal). These might need to be configurable.
*   **Error Handling:** Implement robust error handling for API calls (timeouts, rate limits, invalid responses). Update the `Tender` status or add a log if AI processing fails.

## 6. Technical Considerations

*   **Permissions:** Define Role Permissions for the `Tender` Doctype. Sales Users might create/edit, while Sales Managers might have full access including finalizing or overriding AI suggestions.
*   **Background Jobs:** Essential for AI calls to prevent UI freezes. Use ERPNext's built-in RQ queue. Provide user feedback (e.g., "AI Analysis in progress...").
*   **File Handling:** Ensure secure and efficient handling of potentially large uploaded documents. Consider storage limits.
*   **Logging:** Implement logging for AI requests, responses (or summaries), and errors for debugging purposes.
*   **UI/UX:** Maintain consistency with the standard ERPNext interface. Use clear indicators for AI processes and statuses.
*   **Print Formats:** Create a professional Print Format for the PDF export option in the Finalize step.
*   **Scalability:** Consider the potential load on the AI service and ERPNext if many users analyze large tenders simultaneously.
